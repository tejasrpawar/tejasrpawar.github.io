The other day, I learned about this running joke that the ‘S’ in ‘Docker’ stands for ‘Security’—an impudent way of saying Docker isn’t exactly built with security as its top priority. This was enough to make me ponder about why VMs still exist with the popularity of this ‘lightweight’ container technology. 

Docker is impressive. Containers share the host system’s kernel, so you don’t need a whole separate operating system for each app. Meaning quicker startup time and lesser resources compared to VMs. And as it’s a common knowledge: it solved this riotous ‘iT wORkS oN mY mAChinE’ problem. 

Why aren’t VMs obsolete then? They aren’t. And for good reasons. And the first line of this post answers it. It provides complete isolation(a double-edged sword?).This is key when one needs strong security boundaries. And one must not forget about legacy applications that were designed for specific operating systems—VMs let businesses keep these 'old-but-gold' systems running without a hitch. Docker containers on the other hand share the host system's kernel, meaning if a container exploits a vulnerability in the kernel, it can potentially access the entire host system

Take my situation for example: I’m currently using a Mac, and there are times when I need to run Windows-specific applications. Since macOS doesn’t natively support Windows applications, I must fire up a VM to run Windows on my Mac. 

It is very obvious for the reasons stated above, many organizations use a mix of both Docker containers and VMs to cover all their bases. Containers are awesome. They are great for microservices and apps that need to scale quickly, while VMs handle tasks that require a full OS environment or extra isolation.

This joke was a fun detour. Despite the reputation(or my opinion) of VMs being this bulky old tech, they still are relevant and useful.
